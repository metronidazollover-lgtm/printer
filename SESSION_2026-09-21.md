# Отчёт сессии 2026-09-21

Задача этой сессии: FlyingBear Tornado 2 Pro + Cura 5.10, модель лотоса (`logo.stl`). Крышка над заполнением рваная, на готовом верхе дырки. Нужна рабочая управляющая программа. Отдельно — чтобы агент мог крутить Cura через MCP.

Это отчёт **одной** настройки печати. Для следующих задач читай `AGENTS.md`, а не этот файл как инструкцию «всегда так».

## Что было не так на печати

Исходный `CFFFP_logo.gcode` (Cura 5.10, сопло по сути 0.4):

- infill **10% grid** — клетки ~8 мм;
- мало верхних слоёв (~4);
- кожа крышки печаталась над пустотой → рваный переход infill→skin и дырки на внутренних лепестках.

Модель из Shapr3D очень плотная (~776k треугольников). Cura GUI её режет, standalone CuraEngine на полном JSON-flatten падает (деление на ноль, пустые `infill_angles`).

## Конфиг принтера

Машина в Cura: **Custom FFF printer**.

Стартовый/завершающий G-code уже был правильный (`G28`, `G29`, линии очистки, выезд стола Y300). Один раз профиль слетел: в machine instance повесили кастомный `quality_changes`, Cura пересоздала машину. G-code восстановили из памяти/бэкапа. После этого instance снова на `empty_quality_changes`.

Живой снимок на конец сессии лежит в `printer_configs/cura_5.10_custom_fff/`.

Пользователь **после** слайса сказал, что сопло сейчас **0.6 мм**. В `printer_configs/HARDWARE.md` и в definition_changes экструдера снимка записано 0.6. Переслайс под 0.6 **не делался**.

## MCP

- Поставлен AuraFriday MCP-Link Server 1.3.09, в Cursor сервер `mypc`.
- Плагин CuraMCP то пропадал из `%APPDATA%\cura\5.10\plugins\`, то не держал SSE.
- В Cura 5.10 нет Show Console — это пункт 5.11+.
- MCP-Link 1.3 на регистрацию отвечает JSON `registered_name`, а не текстом `Successfully registered tool`. Плагин считал это ошибкой, отключался, вызовы падали: `Remote tool 'cura' disconnected before replying`.
- После правки регистрации инструмент `cura` заработал: загрузка STL, свойства, слайс, выгрузка `scene.gcode_dict`.
